# Dual 游戏设计

## 1. 抢救结论

`Dual` 值得继续开发。它已经具备一个容易理解、又有对抗深度的独特关系：

```text
短弓命中 -> 击退并制造短暂破绽 -> 长弓寻找致命射击
     ^                                  |
     |                                  v
走位与箭矢拦截 <- 防守、欺骗蓄力和反击时机
```

问题不是创意不足，而是当前游戏只用“一次击杀”就结束对局，反馈和回合结构也不足以让玩家反复理解、练习和反制这套关系。拓展方向应是增加同一组规则产生的决策，而不是尽快堆入更多武器、角色和养成系统。

## 2. 产品定位

`Dual` 是一款 Java + Processing 开发的极简双人战术弓箭对战游戏。玩家通过少量按键完成移动、短弓压制和长弓击杀，在短局内进行读招、走位、拦截与反击。

目标体验：

- 单回合通常持续 20 至 60 秒。
- 一场标准比赛通常持续 3 至 5 分钟。
- 新玩家在第一场内理解“短弓不致命、长弓致命”。
- 熟练玩家能解释自己为什么命中或失误，而不是把胜负归因于随机碰撞。
- 人机、本地双人和联机使用同一套战斗规则，不产生模式专属数值。

## 3. 核心术语

- **短弓**：每次按下自动朝对手瞄准的非致命攻击。职责是逼迫走位、打断节奏并制造破绽，不承担直接击杀。
- **长弓**：需要持续蓄力并在松开后发射的致命攻击。对手进入锁定范围后自动跟踪，范围外允许鼠标手动调整方向；职责是兑现玩家创造出的射击机会。
- **目标操作方案**：`WASD` 移动，鼠标左键短弓，鼠标右键长弓；长弓在范围内自动瞄准，鼠标作为范围外的手动瞄准输入。键盘方案保留为兼容输入，不改变规则。
- **破绽**：角色被短弓命中后的短暂失控状态。破绽必须有明确的剩余时间反馈；它不是生命值损失。
- **箭矢拦截**：敌我箭矢碰撞后相互碎裂。玩家可以用进攻动作保护自己，但必须承担攻击进入冷却或蓄力被打断的机会成本。
- **回合**：从双方出生和倒计时开始，到一方被长弓击杀为止的一段战斗。
- **比赛**：由多个回合组成的完整胜负单位。标准比赛采用先胜三回合。
- **竞技场规则**：只改变空间关系或明确的局内约束，不改变玩家的永久属性。

## 4. 设计支柱

### 4.1 压迫与兑现

短弓负责创造机会，长弓负责兑现机会。两种武器不能只是“低伤害快射”和“高伤害慢射”的数值差异；它们必须形成连续决策：

1. 玩家用短弓限制对方的移动方向。
2. 命中后观察对方被击退的位置与破绽时间。
3. 决定立即蓄力、继续压迫，还是防备对方用箭拦截。
4. 长弓射失会让主动权回到对手手中。

### 4.2 承诺与读招

长弓必须是一项有承诺的动作：蓄力时移动速度降低但不完全锁死，瞄准仍可连续调整，并通过清晰预警让对手有机会闪避或拦截。胜负应来自预判，而不是不可见的瞬发攻击。

目标桌面操作固定为 `WASD` 移动 + 鼠标左键短弓 + 鼠标右键长弓。敌人进入 520 像素锁定范围后，长弓持续自动瞄准敌人；范围外才读取鼠标方向。长弓蓄力期间保留正常移动速度的 50%，快速松开视为取消，达到最低蓄力后松开才发射。提前释放或被短弓命中都会取消当前 `OPENING`，再次蓄力必须重新建立机会。发射后进入 0.35 秒恢复窗口：角色可以正常移动，但暂时不能使用短弓或再次蓄力，角色周围的红色消退弧显示剩余时间。

### 4.3 一切攻击都可互动

飞行中的箭不是单纯伤害判定，而是双方都能处理的场上对象。拦截应保留为核心规则，并通过碎裂效果、声音和短暂停顿让玩家看懂是哪支箭救了自己。

### 4.4 低规则量，高组合度

首个完整版本只保留移动、短弓、长弓和箭矢拦截。新内容必须改变位置、时机或风险判断；仅提供更高速度、更大伤害的同质武器不进入首个版本。

## 5. 标准比赛规则

### 5.1 回合结构

1. 双方在镜像出生点重置位置、速度、箭矢和临时状态。
2. 三秒倒计时期间可以观察场地，但不能移动或射击。
3. 倒计时结束后进入战斗。
4. 长弓命中玩家时，该玩家立即输掉本回合。
5. 显示本回合胜者和总比分，然后开始下一回合。
6. 任一方先取得三回合胜利时比赛结束，玩家可以立即再战或返回模式选择。

回合重置不得重启应用、重新建立网络连接或丢失比赛比分。

### 5.2 平局与停滞

首个版本不设置随机落雷、随机武器或不可预告的强制伤害。若试玩表明玩家会长期消极躲避，再引入有明确倒计时和边界反馈的“决胜阶段”：回合达到 60 秒后，安全区域在 15 秒内向中央收缩。该规则必须经过试玩验证后才能成为默认规则。

### 5.3 短弓节奏

当前 0.2 秒冷却可能鼓励持续按键，并让画面被大量箭矢占据。第一轮平衡实验采用以下假设，而不是直接增加新武器：

- 同一玩家最多连续储备三发短弓机会。
- 使用后按固定时间恢复一发，恢复过程完全可见。
- 恢复或受击结束前六帧内的新短弓按下会被短暂记住，并在首个合法帧执行；缓冲不能绕过弹药、冷却或长弓蓄力承诺。
- 成功出箭后只保留固定四帧快射动作，期间维持完整移动；动作不再由按键松开时机延长，按住也不会自动续射。
- 命中仍只造成击退和破绽，不积累伤害，也不能直接获胜。
- 连续命中不得无限延长破绽；刷新规则必须设上限并由测试固定。

如果试玩证明储备系统增加了不必要的 UI 和计算负担，则退回“固定冷却 + 同屏短箭上限”的更简单方案。选择标准是决策是否更清晰，不是系统是否更复杂。

### 5.4 战术连击

本游戏不采用传统的伤害倍率连击。**战术连击**是一个可解释的事件链：短弓命中并制造破绽，玩家在破绽窗口内开始长弓蓄力，随后长弓命中完成击杀。实现时记录三个独立事件：`PRESSURE`（短弓命中）、`OPENING`（破绽期间开始蓄力）、`FINISH`（长弓命中）。任一环节失败都不应额外扣血或制造隐藏惩罚，只显示实际发生的反馈。

## 6. 信息与反馈

玩家在战斗中必须能立即读懂以下信息：

| 信息 | 表现要求 |
| --- | --- |
| 比分 | 屏幕顶部常驻显示，明确当前回合与先胜目标。 |
| 短弓可用性 | 不遮挡战场的离散格或短条，不只依靠按键无响应表达冷却。 |
| 长弓蓄力 | 角色周围显示连续进度；完成蓄力时颜色和声音同时变化。 |
| 战术机会 | 短弓命中后开始有效长弓蓄力时，锁定环和顶部状态提示显示 `OPENING`；窗口结束后恢复普通锁定颜色。 |
| 蓄力打断 | 短弓命中正在蓄力的对手时显示 `CHARGE BREAK`，并在目标处产生琥珀破裂环与短促命中停顿。 |
| 箭矢拦截 | 两支箭相撞时按单帧连续轨迹和首次接触顺序判定，在真实接触点显示青色碎裂环和短促碎片，区别于角色受击的暖色反馈。 |
| 破绽状态 | 被击退角色周围显示逐渐消退的环，结束时反馈明确。 |
| 角色与 HUD 对比 | 黑白角色使用相反明度的细轮廓；常驻小字号 HUD 在灰色竞技场上保持至少 4.5:1 的明度对比。 |
| 致命轨迹 | 长弓命中后定格真实发射点到碰撞点的有限红色轨迹与破裂标记，再把淡出的同一轨迹带入结算；普通击杀显示 `LETHAL HIT`，只有完整战术链显示 `FINISH`。 |
| 箭矢拦截 | 碰撞点产生区别于普通消失的碎裂效果和声音。 |
| 战术连击 | 按事件顺序显示短促的压迫、机会和兑现反馈，不显示伤害倍率。 |
| 回合结果 | 先显示本回合结果，再更新比赛比分，避免与最终胜负混淆。 |
| 回合报告 | 结算层并列比较双方短弓/长弓命中与发射、蓄力打断，并汇总中立的箭矢拦截和有效战斗时长；只复盘已发生事实，不引入隐藏评分。 |
| 暂停状态 | 冻结最后一帧并覆盖明确的暂停层；真人本地对局失焦时自动暂停，恢复前清空残留输入。 |

视觉仍保持黑、白、灰为主的几何风格；强调色只用于致命威胁、破绽和关键结果。音效应短促并承担信息职责，不依赖持续背景音乐掩盖反馈不足。

## 7. 模式与内容拓展顺序

### 7.1 首发模式

1. **人机练习**：默认入口，支持基础、标准和进阶三档 AI；难度改变决策与反应窗口，不作弊读取未来输入。
2. **本地双人**：作为后续模式单独验证双手柄，或“玩家一鼠标键盘、玩家二手柄”的输入组合；不能假设两个玩家可以共享一个系统鼠标指针。纯键盘双人只作为兼容实验。
3. **联机双人**：沿用同一比赛和回合规则；网络只改变输入来源，不改变战斗数值。

### 7.2 竞技场拓展

在开放竞技场通过试玩后，再按以下顺序加入场地：

- **中央掩体场**：一块固定掩体阻挡箭矢但不产生随机运动，用于创造绕行和预瞄。
- **双通道场**：两块对称掩体形成中间与侧翼射线，检验空间选择。
- **决胜边界场**：只用于验证安全区域收缩，不与其他新机制同时上线。

每张场地必须保持镜像公平、出生点安全和长弓轨迹可读。随机风向、移动墙体、地面陷阱和道具掉落暂不进入首个版本。

### 7.3 长期可选方向

- 每日或自定义规则：短弓数量、长弓蓄力时间、决胜阶段开关。
- 回放种子与输入记录：用于复盘争议命中和调试联机分歧。
- 小型淘汰赛房间：复用已验证的单场比赛，不改变底层战斗。

这些方向只有在标准比赛可稳定重复游玩后才评估。

## 8. 明确不做

- 不加入角色等级、装备数值、抽卡、局外属性或付费战力。
- 不把游戏扩成 RPG、开放世界或剧情战役。
- 不在首个完整版本加入超过两种武器。
- 不用大量随机事件代替玩家之间的预判和反制。
- 不先建设账号、排行榜或复杂匹配，再回头处理基础对战是否好玩。

## 9. 试玩验证

每个可玩里程碑至少完成五场人机和五场真人对局，并记录：

- 单回合与整场比赛时长。
- 短弓发射、命中和连续命中的次数。
- 长弓蓄力、发射、命中和被箭拦截的次数。
- 玩家能否复述死亡原因和一次成功反制。
- 是否出现持续按短弓优于观察时机的情况。
- 是否出现双方超过 60 秒不愿主动进攻的情况。
- 再战选择率以及玩家主动停止的原因。

D1-D6 还必须额外记录：

- 玩家在移动中完成瞄准、蓄力和发射的成功率。
- 从短弓命中到开始长弓蓄力的平均时间。
- 长弓蓄力取消率、误发射率和完成蓄力后的命中率。
- 玩家是否能在不看说明的情况下说出鼠标左右键职责。

若玩家不能解释胜负，先修反馈；若唯一有效策略是短弓连射，先修资源节奏；若有效策略只有等待对手先蓄力，才验证决胜阶段。不要用新增内容掩盖基础规则问题。
