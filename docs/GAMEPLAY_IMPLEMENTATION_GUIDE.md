# Dual 玩法落地开发指导

本文把 [游戏设计](GAME_DESIGN.md) 中已确认的操作与竞技方向翻译成 Java + Processing 的实现边界。它不新增玩法；当本文与代码现状冲突时，实施计划中的当前里程碑优先，完成验证后再更新“当前状态”。

## 1. 已确认决策

| 决策 | 规则 |
| --- | --- |
| 移动 | 目标方案使用 `WASD`，保留方向键兼容映射。 |
| 瞄准 | 短弓始终自动瞄准；长弓在 520 像素内自动锁定敌人，范围外读取鼠标方向。 |
| 短弓 | 鼠标左键或键盘兼容键的每次按下触发一发；非致命，击退并制造破绽。 |
| 长弓 | 鼠标右键或键盘兼容键按住蓄力，松开时发射；蓄力期间减速，不完全锁死。 |
| 连击 | 只记录“短弓制造破绽 -> 长弓完成兑现”的战术事件链，不做伤害倍率。 |
| 兼容性 | 人类、AI、网络玩家都通过同一个 `AbstractInputDevice` 输入意图进入规则。D1-D6 先验证人机主操作，不假设同机两人能共享鼠标。 |

鼠标输入不能直接绕过规则修改玩家角度。输入层只提交“鼠标瞄准方向”和“按钮状态”，长弓状态先判断自动锁定范围，未锁定时才接受鼠标方向。

## 2. 输入架构边界

### 2.1 输入数据

建议把当前离散键盘输入扩展为以下概念，名称可按现有 Java 风格调整：

- `moveX`、`moveY`：范围为 `-1`、`0`、`1` 的移动意图。
- `aimAngle`：相对竞技场坐标的绝对瞄准角，鼠标未在画布内时保留上一帧有效值。
- `shotPressed`、`shotJustPressed`：短弓按钮当前状态与按下边沿；发射只消费按下边沿，不能由持续按住或恢复弹药自动补射。
- `longShotPressed`：长弓按钮当前是否按下。
- `longShotJustPressed`、`longShotJustReleased`：用于区分开始蓄力和松开发射，避免用持续按下状态猜测边沿。

网络报文在 D6 之前不扩展。D1-D5 先让本地输入和 AI 使用新接口；D6 再一次性决定需要同步哪些字段。

### 2.2 坐标转换

鼠标屏幕坐标必须经过现有画布缩放和偏移转换，得到 1280 x 720 内部坐标。画布外的鼠标位置不能产生新的瞄准角，也不能触发武器。角度计算集中在一个可测试函数中，避免 App、玩家状态和网络层各自重复转换。

### 2.3 输入优先级

每帧按以下顺序处理：

1. 读取并归一化输入。
2. 由玩家引擎写入 `AbstractInputDevice`。
3. 当前玩家状态读取移动、瞄准和按钮意图。
4. 状态机决定速度、角度和发射行为。
5. 网络模式只发送规则需要的输入，不发送本地渲染结果。

不要在 `App.keyPressed`、鼠标回调或 UI 绘制函数中直接创建箭矢、修改速度或结算命中。

## 3. 长弓状态设计

长弓至少需要区分以下状态数据：

| 数据 | 作用 | 生命周期 |
| --- | --- | --- |
| `charging` | 当前是否处于蓄力状态。 | 长弓键按下到松开。 |
| `chargeFrames` | 已蓄力帧数。 | 进入蓄力时清零，发射或取消时清零。 |
| `minimumChargeFrames` | 允许发射的最低蓄力。 | 固定规则常量。 |
| `chargeMoveRatio` | 蓄力期间移动速度倍率，当前取候选区间中值 0.5。 | 固定规则常量；若试玩数据表明过慢或过快，再在 D2 内单独调整。 |
| `aimAngle` | 当前绝对瞄准方向。 | 锁定范围内跟随敌人，范围外跟随鼠标；松开后保留用于表现。 |
| `cancelled` | 是否因快速松开或受击取消。 | 当前蓄力周期。 |

规则流程：

1. 长弓键刚按下：进入蓄力，记录起始位置和角度，不发射。
2. 长弓键保持：按 `chargeMoveRatio` 应用移动；每帧重算锁定范围，锁定时跟踪敌人，未锁定时读取鼠标角度；显示预警和蓄力进度。
3. 未达到最低蓄力就松开：取消并显示短促灰色环，不产生长弓箭，蓄力帧数清零。
4. 达到最低蓄力后松开：生成长弓箭，清理蓄力状态，进入移动状态。
5. 蓄力期间被短弓命中：取消并清零蓄力，避免出现“被击退但仍自动秒杀”的不可读结果。

## 4. 短弓资源设计

D3 先实现规则模型，再接 UI。模型必须能在两种方案间切换：

- 方案 A：三发储备，随时间恢复；
- 方案 B：固定冷却，同屏短箭数量上限。

两种方案共用“可发射、消耗、恢复、不可发射原因”接口。这样试玩后回退方案不会重写玩家状态机和 HUD。AI 不能绕过资源检查；测试必须验证玩家、AI、网络输入走相同的发射条件。

## 5. 战术连击事件

事件只描述已发生的事实，不直接修改伤害：

| 事件 | 触发条件 | 允许的后续 |
| --- | --- | --- |
| `PRESSURE` | 短弓命中并造成击退。 | 开始破绽计时。 |
| `OPENING` | 目标仍处于破绽时，攻击者开始长弓蓄力。 | 显示机会反馈。 |
| `FINISH` | 长弓命中并完成击杀。 | 记录本回合结果。 |

事件记录器不应持有玩家、箭矢或 Processing 节点引用；它只接受事件和帧号，方便 JUnit 测试以及未来回放记录。事件超时只影响反馈，不影响基础命中规则。

## 6. D1-D6 具体交付指导

### D1 输入原型

实现目标：桌面玩家可以在移动中用鼠标瞄准，并同时按住长弓。

开发边界：输入接口、屏幕到画布坐标转换、鼠标按钮边沿、键盘兼容映射；不改变武器数值、不加入新场地。

验收指标：

- 鼠标在画布外不改变瞄准，不误触发攻击。
- `WASD`、方向键、鼠标瞄准和键盘兼容攻击均可独立工作。
- 长弓蓄力时移动速度降低但角色仍可移动。
- 松开长弓键只发射一次，快速点击不会产生异常箭矢。

验证：输入转换和按钮边沿 JUnit；桌面完成 10 次“移动 -> 瞄准 -> 蓄力 -> 发射”。

### D2 长弓手感

开发顺序固定为：移动倍率 -> 蓄力取消 -> 完成蓄力反馈 -> 发射恢复时间。一次只改一个变量。

验收指标：

- 玩家无需停下来才能瞄准。
- 蓄力状态、可发射状态和取消状态视觉区别明显。
- 长弓射失后对手有明确反击窗口。
- 记录蓄力完成率、取消率、误发射率和命中率。

### D3 短弓节奏

先实现方案 A 与方案 B 的可切换规则测试，再进行真人试玩。试玩结果只选择一个主方案，不保留两个并行的正式规则。

验收指标：持续按住短弓不应成为稳定最优策略；玩家需要在压迫、保留弹药和防守之间选择。

### D4 战术连击反馈

实现事件记录和表现订阅，不加入伤害倍率。至少覆盖短弓命中、破绽开始、开始蓄力、箭矢拦截和长弓终结。

验收指标：玩家能在回放或试玩后指出自己是否完成了“压迫 -> 机会 -> 兑现”。

### D5 回合与竞技结构

实现先胜三回合、比分 HUD、回合重置、再战和模式返回。D5 不加入中央掩体，避免同时引入空间变量。

验收指标：一场比赛 3 至 5 分钟；回合重置不丢比分、不重启网络连接、不残留箭矢。

### D6 中央掩体竞技场

加入一块镜像中央掩体。掩体碰撞必须与箭矢碰撞使用明确、可测试的规则，不在同一提交中加入第二张地图、道具或网络协议变更。

验收指标：开放场和掩体场均无出生优势；掩体能创造绕行、预瞄和短弓逼位选择，又不会造成持续躲藏的稳定最优策略。

联机输入字段、比分同步和再战协议放在 D1-D6 验证完成后的独立阶段处理，不能为了复用旧报文削弱已确认的鼠标瞄准体验。

## 7. 提交与回退规则

- D1-D6 每个阶段拆成多个小提交；输入、长弓、短弓、反馈、回合、场地/联机不得混成一个提交。
- 每个规则提交必须先有 JUnit 或协议测试，再做桌面试玩。
- 试玩失败时优先回退最近一次数值或反馈提交，不重写已经验证的输入边界。
- 如果鼠标方案在真实试玩中仍显著困难，保留键盘兼容方案，但不要同时维护两套不同的战斗规则。

## 8. 暂停条件

- 玩家仍无法同时移动、瞄准和蓄力：停止增加内容，重新检查输入边沿和坐标转换。
- 玩家无法解释长弓为什么取消或命中：停止平衡调整，先修状态反馈。
- 短弓连射仍然最优：停止做地图，先完成 D3 资源节奏。
- 掩体导致某一侧稳定胜率更高：停止增加场地，先修镜像布局和出生保护。
- 联机出现比分分歧：停止网络扩展，先补充确定性输入与结果测试。
