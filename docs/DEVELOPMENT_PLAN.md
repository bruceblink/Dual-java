# Dual 开发计划

## 项目定位

- `Dual` 是持续开发的 Java 双人弓箭对战游戏，不是等待被其他工程替代的冻结 Demo。
- 客户端继续使用 Java 21 + Processing，构建、测试和打包继续由当前 Gradle 工程负责。
- `server` 中的 Java Relay 属于 `Dual` 的联机能力；后续是否升级房间、同步或权威判定，也在本项目内按实际玩法需求评估。
- `dual-game-client` 是另一款独立的 Godot 游戏。它与 `Dual` 不共享产品路线、版本、代码或发布计划。

详细技术边界见 [技术路线说明](TECHNOLOGY_EVALUATION.md)。

## 当前玩法基线

- 两名角色在 640 x 640 竞技场中进行本地人机或双人联机对战。
- 短弓自动瞄准并击退对手，主要用于压迫走位和创造机会。
- 长弓需要蓄力和手动瞄准，命中后直接击杀；蓄力期间角色移动与瞄准受到限制。
- 双方箭矢可以互相碰撞并碎裂，因此进攻同时也是防守资源。
- 当前对局以单次击杀决定胜负，结束后返回演示模式。

## 近期方向

1. 先强化上述“短弓创造位置优势、长弓完成击杀、箭矢互相抵消”的核心博弈。
2. 通过局内目标、场地规则和回合结构增加变化，不用无关系统稀释双人弓箭对抗。
3. 改进本地人机、双人操作与联机流程，使新增玩法在三种对局方式下保持一致。
4. 在核心循环稳定后，再评估角色差异、更多武器或长期成长系统。

## 工程质量门槛

- 每个小功能使用 Java 实现，并配套与风险相匹配的 JUnit、Gradle 构建或实际运行验证。
- 每个完成且验证通过的小功能独立提交；部分完成或验证失败的内容不提交为完成状态。
- 改动战斗规则时优先补充可重复的规则测试，避免依赖随机表现判断正确性。
- 改动联机协议时同时验证消息编解码、断线行为和双方输入一致性。
- Windows 发布包继续使用当前 `jpackage` 流程；新增目标平台前单独评估 Processing 与打包支持。

## 当前不做

- 不把 `Dual` 迁移到 Godot，也不把另一个 Godot 游戏描述为 `Dual` 的正式版本。
- 不因为另一个项目的技术选择而替换 `Dual` 的 Java 客户端或 Java Relay。
- 不在核心对战尚未验证前引入账号、商城、大型剧情或重型养成系统。
